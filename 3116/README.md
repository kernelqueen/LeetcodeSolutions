# 3116. Kth Smallest Amount With Single Denomination Combination

**Difficulty:** Hard

**Topics:** Binary Search, Inclusion-Exclusion, Number Theory, LCM, Bitmasking

---

## Problem

You are given an integer array `coins` representing different coin denominations and an integer `k`.

You have an infinite number of coins of each denomination. However, you are **not allowed to combine coins of different denominations**.

This means each denomination can only generate its own multiples.

Return the **kth smallest distinct amount** that can be made.

---

## Examples

### Example 1

```text
Input:
coins = [3, 6, 9]
k = 3

Output:
9
```

The possible amounts are:

```text
3, 6, 9, 12, 15, ...
```

The 3rd smallest amount is `9`.

### Example 2

```text
Input:
coins = [5, 2]
k = 7

Output:
12
```

The distinct amounts are:

```text
2, 4, 5, 6, 8, 10, 12, 14, 15, ...
```

The 7th smallest amount is `12`.

---

## Initial Approach

My first thought was to solve this using **simulation**.

For every denomination, we can generate its multiples:

```text
2 → 2, 4, 6, 8, 10, 12, ...
5 → 5, 10, 15, 20, ...
```

Then we could merge the generated values, remove duplicates, and find the kth smallest amount.

However, this approach is not feasible because:

```text
1 <= k <= 2 * 10^9
```

Generating values until the kth amount could require billions of operations.

So instead of generating the values, we need to find a way to **count** how many valid amounts exist up to a given value.

---

## Pattern Identification

The important observation is:

> Instead of directly finding the kth smallest amount, we can check how many valid amounts are `<= x`.

Let:

```text
count(x)
```

represent the number of distinct valid amounts less than or equal to `x`.

Then:

```text
if count(x) >= k
    x can be the answer

if count(x) < k
    x is too small
```

Since `count(x)` is monotonic, we can apply:

```text
Binary Search on Answer
```

The overall pattern becomes:

```text
Kth Smallest
     ↓
Can we count values <= X?
     ↓
Count using Inclusion-Exclusion
     ↓
Binary Search on Answer
```

---

## Counting Multiples

For a single coin denomination `coin`, the number of multiples less than or equal to `x` is:

```text
x / coin
```

For example:

```text
x = 12
coin = 5
```

Then:

```text
12 / 5 = 2
```

The multiples are:

```text
5, 10
```

---

## The Duplicate Problem

When there are multiple denominations, some amounts can be generated by more than one denomination.

For example:

```text
coins = [2, 5]
x = 12
```

Multiples of `2`:

```text
2, 4, 6, 8, 10, 12
```

Count:

```text
12 / 2 = 6
```

Multiples of `5`:

```text
5, 10
```

Count:

```text
12 / 5 = 2
```

Simply adding them gives:

```text
6 + 2 = 8
```

But `10` has been counted twice.

We need to subtract the overlap.

---

## Inclusion-Exclusion

The common multiples of two numbers are multiples of their:

```text
LCM
```

For `2` and `5`:

```text
LCM(2, 5) = 10
```

Therefore:

```text
count(12)
= 12 / 2 + 12 / 5 - 12 / 10
= 6 + 2 - 1
= 7
```

The seven distinct amounts are:

```text
2, 4, 5, 6, 8, 10, 12
```

Therefore `12` is the 7th smallest amount.

---

## Handling Multiple Coins

For more than two denominations, we use the **Inclusion-Exclusion Principle**.

For every non-empty subset of coins:

* If the subset contains an odd number of coins, add its contribution.
* If the subset contains an even number of coins, subtract its contribution.
* The contribution is the number of multiples of the LCM of the selected coins.

For a subset with LCM `L`:

```text
contribution = x / L
```

For example, with:

```text
coins = [2, 3, 5]
```

the calculation follows:

```text
x/2 + x/3 + x/5
- x/LCM(2,3)
- x/LCM(2,5)
- x/LCM(3,5)
+ x/LCM(2,3,5)
```

---

## Why Bitmasking?

The constraint is:

```text
coins.length <= 15
```

Therefore, the maximum number of subsets is:

```text
2^15 = 32768
```

This is small enough to enumerate every subset.

A bitmask represents which coins are selected.

For example:

```text
coins = [2, 3, 5]
mask = 101
```

means:

```text
2 → selected
3 → not selected
5 → selected
```

So the selected subset is:

```text
[2, 5]
```

For each subset, we calculate:

1. Number of selected coins.
2. LCM of the selected denominations.
3. Number of multiples `<= x`.
4. Whether to add or subtract using Inclusion-Exclusion.

---

## Binary Search

The smallest possible answer is:

```text
1
```

For the upper bound, we can use:

```text
min(coins) * k
```

Because if `m` is the smallest denomination, then:

```text
m, 2m, 3m, ..., km
```

already gives us `k` valid amounts.

Therefore:

```text
low = 1
high = min(coins) * k
```

We search for the smallest value satisfying:

```text
count(x) >= k
```

### Binary Search

```text
while low < high:

    mid = low + (high - low) / 2

    if count(mid) >= k:
        high = mid
    else:
        low = mid + 1
```

At the end:

```text
low
```

is the kth smallest amount.

---

## Complete Java Solution

```java
class Solution {

    public long findKthSmallest(int[] coins, int k) {

        long minCoin = Integer.MAX_VALUE;

        for (int coin : coins) {
            minCoin = Math.min(minCoin, coin);
        }

        long low = 1;
        long high = minCoin * (long) k;

        while (low < high) {

            long mid = low + (high - low) / 2;

            if (count(mid, coins) >= k) {
                high = mid;
            } else {
                low = mid + 1;
            }
        }

        return low;
    }

    private long count(long x, int[] coins) {

        int n = coins.length;
        long total = 0;

        // Enumerate all non-empty subsets
        for (int mask = 1; mask < (1 << n); mask++) {

            long lcm = 1;
            int selected = 0;

            for (int i = 0; i < n; i++) {

                if ((mask & (1 << i)) != 0) {

                    selected++;

                    lcm = getLCM(lcm, coins[i]);

                    // No multiple of this LCM can be <= x
                    if (lcm > x) {
                        break;
                    }
                }
            }

            if (lcm > x) {
                continue;
            }

            long multiples = x / lcm;

            // Inclusion-Exclusion
            if (selected % 2 == 1) {
                total += multiples;
            } else {
                total -= multiples;
            }
        }

        return total;
    }

    private long getGCD(long a, long b) {

        while (b != 0) {

            long temp = a % b;
            a = b;
            b = temp;
        }

        return a;
    }

    private long getLCM(long a, long b) {

        return (a / getGCD(a, b)) * b;
    }
}
```

## Dry Run

Consider:

```text
coins = [5, 2]
k = 7
```

Suppose binary search checks:

```text
x = 12
```

### Subset `{2}`

```text
12 / 2 = 6
```

Since one coin is selected:

```text
+6
```

### Subset `{5}`

```text
12 / 5 = 2
```

Since one coin is selected:

```text
+2
```

### Subset `{2, 5}`

```text
LCM(2, 5) = 10

12 / 10 = 1
```

Two coins are selected, so:

```text
-1
```

Therefore:

```text
count(12) = 6 + 2 - 1
          = 7
```

Since:

```text
count(12) >= k
7 >= 7
```

`12` is a valid candidate.

Binary search eventually finds:

```text
answer = 12
```

---

## Complexity Analysis

Let:

```text
n = coins.length
```

There are:

```text
2^n
```

possible subsets.

For every subset, we may process up to `n` coins to calculate the LCM.

Binary search requires:

```text
O(log(min(coins) * k))
```

iterations.

### Time Complexity

```text
O(2^n * n * log(min(coins) * k))
```

With:

```text
n <= 15
```

this is feasible.

### Space Complexity

```text
O(1)
```

No additional DP table or collection is required.

---

## Final Pattern

The main pattern I took away from this problem is:

```text
Kth Smallest Value
        ↓
Binary Search on Answer
        ↓
Count how many valid values <= X
        ↓
Inclusion-Exclusion
        ↓
LCM for overlapping multiples
        ↓
Bitmasking to enumerate subsets
```

The key shift from the initial simulation idea is:

```text
Generate values ❌

Count values <= X ✅
```

When `k` is extremely large and the counting function is monotonic, **Binary Search on Answer** becomes a strong candidate.

For this problem, **Inclusion-Exclusion + LCM** provides the required counting function efficiently.
